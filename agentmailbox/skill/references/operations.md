# 本机消息服务维护

日常发信、取件见[技能入口](../SKILL.md)，字段和状态见[协议](protocol.md)。本页供安装、升级、停启与对账时使用。

## 组件与数据

- `agent-mailbox`：独立 Go 服务，保存成员、消息、领取和回执，只监听私有 Unix socket。
- `cc_adapter.py`：机械接入程序，读取配置中指定的 CC 聊天索引，经已有 IPC 核实身份后登记和投递。
- Hermes 插件与桃乐丝 invocation hooks：随任务加载，在模型调用边界取件；执行结束即释放模型槽。
- `mailbox.py` / MCP：使用自身固定绑定查看成员、发信、取件和确认。

默认运行根为 `CC_DATA_DIR/mailbox`；未设置 CC_DATA_DIR 时是 `~/.cc-connect/mailbox`。运行根含服务的 `api.sock`、`mailbox.sqlite3`、`admin-token` 及接入端私有绑定/登记记录。需要其他路径时明确设置服务参数和接入配置，不能只改一端。

数据库、令牌、绑定、作业快照和下游投递记录共同用于恢复；这些运行资料留在私有目录。发布清单只收录源码、测试和无凭据的配置样例。

## 安装与升级

构建模块：

```sh
go build -o agent-mailbox ./cmd/agent-mailbox
./agent-mailbox version
./agent-mailbox serve --runtime /绝对路径/私有运行目录
```

服务创建私有运行目录并取得排他锁。它可以在没有 CC Connect 的环境中运行，原生客户端也可直接使用。

CC 接入单独配置已授权的项目、完整聊天索引位置、宿主工作目录和 CC socket，再启动 `cc_adapter.py --config /绝对路径/接入配置.json`。具体配置以交付版本附带样例为准。它经 `/ipc/chat-target` 核对聊天，通过 `/ipc/event` 投递；无需替换 CC 二进制或重启 CC。

在 macOS 下，服务和 CC 接入程序分别交给自己的 launchd 项管理。安装或升级前记录当前文件摘要与恢复副本；只替换本批清单文件，不覆盖其他成员的在途改动。任务入口的插件和配置按任务固定，既有未接入进程继续按原配置运行，新任务使用新版本。

## 核对是否可用

在当前 CC 聊天执行 `mailbox.py doctor`，核对服务协议和自身 mailbox；`peers` 查看允许联系的成员。同一任务组的 Hermes 和桃乐丝应互相可见，各自还能联系原 Atlas。目录、昵称、模型线程都不能代替稳定邮箱编号。

显式要求 `--team` 时，登记或接入条件未满足会在启动模型前失败。普通未要求通信的旧调用仍可继续原来的任务能力；查回执区分“任务已受理”和“通信已接入”。

完整现场验收还应包括双方执行中发信/回复、Atlas 当前聊天收件，以及新服务停启后原消息可查。健康接口成功不能代替这些实际往返。

## 结果不明与恢复

先读取原消息及原领取证据。`accepted` 表示执行器接纳，`received_at` 表示成员显式确认，两者都不代表任务完成。`dispatching` 或 `unknown` 需要沿原 message/attempt 对账；不清回执、不换编号、不把消息改回 pending。

CC 投递记录保存原事件和实际收件目标。已可能发送的事件先查询原 `/ipc/event?event_id=...`；仅在原接收端明确证明尚未提交时才可按同一事件重试。`/new` 只影响后续新投递的实际线程，不让已送达或不明事件重新发送。

任务退出后 mailbox 保留，后续使用原任务入口准确续谈；新执行使用新 generation。旧代次结束后不能重新激活，心跳过期本身不能证明执行者已经退出。

服务升级、退出或重启不删除数据库、不取消模型，也不删除另一存活服务的 socket。停启操作只针对本服务及其接入程序，恢复后核对原消息、原登记和新启动身份。CC Connect 的进程、启动时间和二进制摘要可单独比较，确认其未被重启或替换。

## 容量和目录

工作区入口分别允许 6 个 Hermes 与 6 个桃乐丝主任务。供应商请求额度单独计算，子 Agent 请求也会使用供应商额度。

公共父目录不能成为单任务独占的 CWD；具体任务目录、独立 Git 工作树可以使用。研究同一份材料时为每任务分配独立执行目录，Hermes 使用 `--source` 读取共享材料。相同或嵌套写目录继续互斥，不能通过删除锁解除拥堵。
